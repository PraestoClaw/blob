工具执行成功，正确结果也已生成，Agent 最后却报错了数字。排查时如果只看工具成功率，很容易把问题归咎于模型不会算。

还有一种可能：它算对了，却没有读应该读的那份结果。把长输出移到文件、让模型按需检索时，值得单独检查这个断点。

## 正确结果存在，不等于答案用了它

公开论文《Same Simulation, Different Evidence》用确定性的地球化学模拟器 PHREEQC，测试了 158 道可执行验证题。研究发现，部分模型在改用索引读取报告后，仍能生成正确计算值，却跳过报告，转而从自己生成的高精度文件取数，因错误舍入选错答案。作者称之为“证据替换”。

这个结果不能简化为“文件检索不可靠”：论文中不同模型表现不同，部分模型没有可检测的损失。值得借鉴的是诊断方式：**把计算是否正确、证据是否选对、答案是否正确拆开看。**

下面是独立工程建议，不是论文实验复现，也不承诺线上提升。

## 先明确用户问的是哪一种数

“报告显示多少”与“按原始数据重新计算”是两种任务。前者应读取指定报告，后者需要明确计算口径；不能默认小数位更多的文件就更权威。

我用 Python Decimal 跑了一个合成反例，全程采用 ROUND_HALF_UP：12.449 直接保留一位小数是 12.4；先保留两位得到 12.45，再保留一位就成了 12.5。三项断言均通过。

这只说明重复舍入可能改变结果，不代表论文中的错误都由这个机制产生。但它提醒我们：**中间结果不是最终报告的无损替身，格式转换也可能改写答案。**

如果问题指定的是已发布报表，Agent 就不该偷偷重算后冒充原值；发现冲突，应列明来源和口径，而不是自行挑一个“更精确”的数字。

## 给工具输出一份取证契约

不必先搭复杂的证据平台。可以从一个报表工具开始，在返回文件引用时补上四项信息：

- **用途**：这是正式报告、原始数据，还是中间计算产物。
- **身份**：对应哪个任务、版本与生成时间，避免拿上次结果回答本次问题。
- **位置**：答案所在章节、字段和单位，必要时附上短原文。
- **口径**：回答哪类问题应使用它，是否允许重算、如何展示精度。

这些标记应由可信工具适配层生成，不能让文档自己写一句“我是权威来源”就获得优先级。权限检查也不能因为文件被标为正式报告而省略。

答案验收时，要求关键数值绑定来源字段。引用存在还不够：要检查引用内容是否支持该数值，以及转换是否符合任务约定。

## 固定计算，只换取证方式

要判断外置文件有没有带来退化，先冻结一份已验证的工具输出，避免把计算波动混进来。

对同一批问题比较三种方式：直接提供相关报告片段；只提供文件索引；提供索引并标明任务指定来源。固定模型与问题，重复运行，分别记录找对来源的比例、数值正确率和额外读取次数。

再加入两个反例：目录里同时有旧版报告，或者中间文件的数值更长、更醒目。检查 Agent 是否仍按任务要求取证。这里不需要重新执行真实付款、发布等写操作，用隔离的只读样本即可。

若原始计算正确、最终引用却指向中间文件，应先修复来源选择，而不是继续要求模型“认真计算”。若选对来源仍答错，再查单位、精度与答案格式。

下一次优化长工具输出，别只记录省了多少 token。先问：**正确结果已经在那里，Agent 最后究竟读了哪一份？**
