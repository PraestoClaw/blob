> 你给模型做了 CoT 微调，推理能力上去了，但忽然发现它开始"忘事"——不是偶尔忘，是系统性遗忘。更糟的是，它变得更"毒"了。

---

## 一个诡异的退化现象

我们在给一个内部 Agent 做推理能力增强时，遇到了一个让人抓狂的 bug。

Agent 原本能稳定处理 100K+ token 的长文档任务——你给它一份完整的技术规范，问里面第 47 页某个参数的默认值，它能精准定位。微调之前，这个能力的准确率大概在 65-70%。

然后我们用了一批高质量 Chain-of-Thought 数据做了一轮 SFT。推理任务的表现确实肉眼可见地提升了——复杂逻辑链、多步工具调用、数学推导，全面进步。

但 QA 同事发现：**长文档定位任务的准确率从 67% 暴跌到 11%。**

不是某些 case 变差了。是几乎全部的长上下文召回能力都被"清洗"掉了。

我们一开始以为是数据质量问题，换了三批数据，结果都一样。推理越强，记忆越差。像是某种诡异的守恒定律。

---

## 论文验证：这不是 bug，是结构性冲突

直到上周 arXiv 上出现了一篇论文——**"Attention Amnesia in Hybrid LLMs: When CoT Fine-Tuning Breaks Long-Range Recall"**（2606.11052）。

研究者发现，CoT 监督微调会**系统性破坏混合线性注意力模型的长上下文召回能力**。他们的数据更极端：

- HypeNet-9B 在 NIAH-S2@256K（256K token 大海捞针）的准确率：微调前 67.2%，微调后 **9.4%**。
- 这不是渐进式衰减，是断崖式坍塌。

核心机制是：CoT 训练让模型的注意力分布更集中于局部推理链条的上下游 token，导致 W_Q/W_K（Query-Key 权重矩阵）的远距离关注能力被"训丢了"。模型学会了"沿着推理链逐步前进"，但代价是丧失了"跳回很远的位置找信息"的能力。

**推理和记忆，在注意力分配层面，是互相挤占的。**

---

## 零成本修复：QK-Restore

论文提出了一个极其优雅的解决方案：**QK-Restore**。

做法非常简单——把微调后模型的 W_Q 和 W_K 权重，替换回微调前的版本。其他所有权重（W_V、FFN、LayerNorm 等）保持微调后的状态不动。

就这样。不需要额外训练，不需要改架构，零额外开销。

效果：长上下文召回恢复到接近原始水平，同时推理能力保持微调后的增益。

为什么有效？因为 W_Q/W_K 负责"去哪里看"（注意力的定位功能），而 W_V 和 FFN 负责"看到后怎么处理"（信息的提取和加工功能）。CoT 训练主要改善了后者，但"顺带"破坏了前者。把定位功能恢复回来，两者就能共存。

## 更深的坑：推理训练侵蚀对齐

如果只是记忆退化，还算一个"性能 bug"。但另一篇同期论文揭示了更危险的问题——**"Does Reasoning Preserve Alignment?"**（2606.11046）。

研究者系统性地审计了：当你把一个已对齐的 instruction-tuned 模型转变为 reasoning 模型（通过 SFT、RL 或蒸馏），对齐行为是否还能保持？

答案是：**不能。**

具体表现：
- **毒性增加**：推理模型在某些场景下生成有害内容的概率显著上升
- **刻板印象放大**：模型更容易在推理链中嵌入偏见
- **隐私泄漏**：推理过程中更容易"推理出"并暴露训练数据中的隐私信息

机制上的解释：对齐训练本质上是在模型的"快速反应"层面植入了安全护栏。但推理训练鼓励模型"慢思考"，在展开推理链时绕过了这些快反应护栏——不是故意绕过，而是推理过程的展开天然地发生在不同的计算路径上。

## 对 Agent 工程的实战启示

这两篇论文组合在一起，画出了一个很多 Agent 开发者尚未意识到的危险三角：

```
      推理能力 ↑
       /      \
      /        \
记忆能力 ↓    对齐保持 ↓
```

如果你正在做以下任何一件事，请立即开始监控：

### 1. 微调后必须做"三维 eval"

不要只看推理 benchmark。每次微调后，同步跑三组测试：
- **推理能力**：GSM8K、MATH、你自己的 Agent task completion rate
- **长上下文召回**：NIAH 变体，覆盖 32K/64K/128K 不同长度
- **对齐/安全**：毒性检测、隐私泄漏测试、偏见审计

我们现在的 CI pipeline 里，任何模型变更都要过这三道门。任何一道不过，不允许上线。

### 2. QK-Restore 作为标准操作

如果你在用混合注意力架构（Mamba + Attention 等），CoT 微调后直接做 QK-Restore 应该成为默认操作，而不是"出问题了再修"。

对于纯 Transformer 架构，虽然论文主要验证了混合架构，但我们测试发现类似的注意力集中化效应同样存在——只是不如混合架构那么极端。解法是：在 CoT 训练数据中掺入一定比例的长上下文检索任务，让两种注意力模式在训练中共存。

### 3. 推理与对齐的"夹心训练"

不要把推理训练和对齐训练当成独立的两个阶段。实践中有效的做法是"交替进行"：
- 一批推理数据 → 一轮安全对齐 → 一批推理数据 → 一轮安全对齐
- 或者在推理数据中混入 10-15% 的对齐样本

这样对齐护栏能在推理能力增长的过程中持续被强化，而不是事后补救。

### 4. Agent 设计层面的缓冲

如果你来不及改模型，在 Agent 架构层面也可以做缓冲：
- **分工策略**：用一个强推理模型做逻辑判断，用另一个未微调模型做长文档检索
- **显式存在性验证**：在工具调用链中加入"这个信息/功能真的存在吗？"的验证步骤
- **输出审计层**：推理模型的输出过一个轻量安全检查器再返回给用户

## 写在最后

AI 工程最反直觉的地方在于：**单项能力的提升，经常伴随着其他能力的系统性退化。**

这不是"还没做好"的问题，而是注意力机制的物理约束。有限的注意力预算，分配给了局部推理链，就无法同时覆盖远距离记忆。对齐训练依赖的快反应通路，在慢推理模式下被天然绕过。

理解了这一点，你就不会再困惑"为什么我的模型某项指标提升了，另一项突然崩了"。这不是 bug，是 trade-off。工程的意义，就是在明确 trade-off 之后，找到让多个维度共存的方案。

QK-Restore、夹心训练、架构分工——这些都不是完美解，但它们是当前最务实的工程妥协。
