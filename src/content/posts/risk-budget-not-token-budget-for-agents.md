模型变便宜，是 AI 创业者最容易误读的好消息。

最近一轮模型发布里，旗舰能力继续上探，轻量模型的速度和单价也都在下降。团队很自然会问：既然每百万 token 更便宜了，能不能把 Agent 多跑几轮、多开几个并行分支，让它更“自主”？

我的答案是：可以增加推理预算，但不要把它当成唯一预算。**Agent 真正稀缺的，不是 token，而是它替用户承担错误后果的额度。**

一次多跑三轮检索，代价可能只是几分钱；一次把错误的合同摘要写回 CRM、把未确认邮件发给客户，代价却是信任、合规和人工补救时间。模型单价下降，后者并不会随之下降。

## 为什么 Token 预算会把团队带偏

AI 团队很容易把 Agent 优化简化成延迟、token 和成功率。但“任务成功”并不能表达后果差异：给内部文档加标签和删除客户记录，在日志里都可能只是一次调用成功；前者错了可重跑，后者可能触发审计。

所以不要只问“这一步值不值得多花 2,000 token”，还要问：

- 它是否改变了外部世界，还是只生成候选内容？
- 错误是否可逆，恢复成本是多少？
- 依据来自系统返回的事实，还是模型的猜测？
- 失败后能否定位到对象、版本与操作者？

这四个问题的答案，才决定自动化可以走多远。

## 用三档风险预算设计行动

一个小团队不需要复杂的风控平台。先把工具调用分成三档，就足以改变系统行为。

**第一档：低风险。** 搜索、读取、草拟、分类、生成预览。允许并行尝试和自动重试，因为错误主要消耗机器成本。

**第二档：有限风险。** 创建草稿、更新可回滚字段、向内部频道发消息。要求携带对象 ID、版本号与变更 diff，并留下可撤销记录。

**第三档：高风险。** 外发、付款、删除、发布、权限变更。默认不直接执行；Agent 负责验证对象、汇总证据和生成预览，最后一步交给人或独立策略层确认。

人工应消耗在不可逆的最后一公里，而不是替 Agent 重做检索和整理证据。

## 风险预算必须和证据绑定

许多产品只做了权限控制：用户有管理员身份，Agent 就能删；用户没有，就不能删。这还不够。

即使权限正确，Agent 仍可能找错对象、使用旧版本，或者把模糊指令理解错。因此每次可能产生副作用的行动，都应有最低证据门槛：

1. **唯一对象**：从工具返回的 record ID、file ID 或订单号，而不是“最像的搜索结果”。
2. **当前状态**：行动前重新读取版本、权限和关键字段，不信任上轮对话里的记忆。
3. **变更预览**：明确展示谁、什么字段、从什么改成什么，以及影响范围。
4. **可审计回执**：记录请求、证据、策略判定、执行结果和回滚入口。

证据不够时，正确动作不是“尽力完成”，而是继续检索或追问，避免错误链进入高风险区。

## 把预算写进产品指标

除任务完成率和平均 token 外，再看四项：高风险动作的人工确认率、证据不足时的正确拦截率、可逆操作的回滚率，以及异常恢复时间。

早期“被拦截”的比例可能上升。这不是 Agent 变笨，而是过去被成功率掩盖的模糊请求开始显形。

模型竞争会继续把智能变成更便宜的基础设施。真正拉开差距的，不是谁让 Agent 多想了十秒，而是谁能清楚回答：**这次行动最多允许错到什么程度；一旦错了，系统怎样把损失锁在边界内。**

给 Agent 增加 token 预算，能提高它的上限；给它风险预算，才能守住产品的下限。
