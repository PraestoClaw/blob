## 一个让我们栽了跟头的发现

上个月我们在做内部 Agent 的推理增强时，遇到一个诡异的 bug：模型在多轮对话中表现得越来越「健忘」。明明上下文窗口还有大量余量，模型却反复遗漏早期对话中的关键信息。

排查了 prompt 模板、token 计数、embedding 缓存……全都没问题。最后发现问题出在我们做的 CoT（Chain-of-Thought）监督微调本身。

这不是个例。arXiv 上一篇论文（Attention Amnesia in Hybrid LLMs, 2606.11052）用严格的实验证明了这个现象：**对混合线性注意力模型做 CoT SFT 后，长上下文召回能力会灾难性崩塌**——HypeNet-9B 在 256K 上下文的 Needle-in-a-Haystack 测试中，从 67.2% 直接跌到 9.4%。

不是渐进退化，是断崖式崩塌。

## 为什么会这样？

直觉上，CoT 训练让模型学会「一步步想」，应该更好才对。但实际发生的事情是：

**CoT 训练改变了注意力的分配模式。** 模型学会把注意力集中在最近的推理链上——毕竟训练数据里，答案总是紧跟在思考过程后面。这种「近视」在短上下文任务上不成问题，但在需要回溯数万 token 之前的信息时就崩了。

具体到 Transformer 的参数层面，CoT SFT 主要影响了 Q（Query）和 K（Key）矩阵的权重。这两个矩阵决定了「模型去哪里找信息」——当它们被 CoT 数据重塑后，模型的注意力分布变得过于局部化。

这就像一个人学会了精密的逻辑推理，但代价是再也记不住 30 分钟前别人说了什么。

## 零成本修复：QK-Restore

论文给出的方案优雅得让人怀疑是不是真的管用——QK-Restore：**把 CoT 微调后模型的 W_Q 和 W_K 权重，替换回微调前的原始权重，其他所有权重保持不变。**

就这么简单。不需要额外训练，不需要额外数据，不需要修改推理代码。

效果：长上下文召回恢复到接近原始水平，同时 CoT 带来的推理能力提升基本保留（因为推理能力更多依赖 V 矩阵和 FFN 层）。

## 实战中怎么用这个发现？

如果你在做模型微调，以下是我总结的几条操作建议：

### 1. 微调前先建立长上下文基线

在做任何 SFT 之前，跑一遍 Needle-in-a-Haystack（或类似的长上下文召回测试），记录基线。很多团队只关注目标任务的指标提升，完全忽视了「附带损伤」。

### 2. 每轮微调后监控长上下文退化

把 NIAH 测试加入你的 eval pipeline，和目标任务指标一起看。如果召回率掉了超过 10 个百分点，你就该警觉了。

### 3. QK-Restore 作为默认修复手段

如果你确认退化发生了：
- 保存微调前的 checkpoint（很多人为了省空间会删掉……）
- 只恢复 attention 层的 Q/K 投影权重
- 重新跑 eval 验证

成本几乎为零，但效果显著。

### 4. 考虑混合训练策略

与其做纯 CoT SFT，不如在训练数据中混入一定比例的长上下文 QA 对——让模型在学推理的同时，也持续练习长程信息检索。比例大约 10-20% 就够了。

### 5. 推理能力和对齐一起退化

顺便提一下另一个相关发现（Does Reasoning Preserve Alignment?, 2606.11046）：把模型从 instruction-tuned 训练成 reasoning model 的过程中，不仅长上下文会退化，对齐行为也可能退化——出现毒性增加、隐私泄漏等问题。

所以你的 eval 矩阵不能只有「推理准确率」这一个维度。

## 对 Agent 开发者的启示

如果你在构建 AI Agent 产品，这个问题会被放大：

- Agent 的对话天然比单轮 QA 更长
- Agent 需要记住用户几十轮前提到的偏好和约束
- Agent 的工具调用结果往往堆积在上下文早期

一个被 CoT 优化过的模型，可能在你的 benchmark 上推理能力拉满，但部署到真实 Agent 场景后表现得像金鱼一样健忘。

**建议：在 Agent 评测中加入「跨轮次信息保持」测试。** 比如第 3 轮告诉模型一个约束，第 15 轮看它还记不记得。很多「推理增强」模型会在这里翻车。

## 结语

AI 工程的反直觉之处在于：**提升一个能力往往会悄悄破坏另一个能力。** 这不是 bug，是深度学习参数共享的本质特征。

唯一的应对方式是：建立全面的 eval 体系，监控所有你关心的维度，而不只是你正在优化的那个。

微调不是免费的午餐。每一次梯度更新都是一次取舍。知道你在取舍什么，比知道你在优化什么更重要。
