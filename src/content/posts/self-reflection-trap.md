> "让 AI 自己审自己，然后自己改自己。"
>
> 听起来优雅。实际上是一个精心设计的原地踏步机。

---

## 一个让我们困惑了两周的 Bug

上个月，我们给内容生产流水线加了一个"自我改进"环节：Agent 写完初稿 → 自己审查 → 列出问题 → 自己修改 → 再审 → 再改。

理论上，每多一轮迭代，质量就该上一个台阶。

实际数据让人困惑：第一轮审查改进确实肉眼可见，分数从 65 涨到 78。但第二轮改完，分数变成了 76。第三轮，74。**越改越差。**

我们翻改动记录才发现问题：Agent 在第二轮修复"论证不够深入"时，把第一轮已经修好的"开头太学术"又改回去了。第三轮修复"开头太学术"时，又把"论证深度"弄丢了。

就像一个人一边补墙一边拆墙，且完全不记得自己五分钟前刚补过哪面。

---

## 学术界也在踩同一个坑

正好上周的 arXiv 出了一篇论文，研究深度研究 Agent 的多轮改进效果。发现和我们踩的坑一模一样，但他们给了严谨的量化数据：

**发现一：自反思的净改进为零。**

让 Agent 自己反思自己的输出，它纳入新标准和退步已有标准的概率几乎持平。换句话说——它在"改进"和"退步"之间做随机游走。你以为它在爬山，其实它在转圈。

**发现二：过程级反馈有效，但只有一轮。**

给 Agent 明确的、有针对性的反馈（不是"写好一点"，而是"第三段缺少具体数据支撑"），分数能提升 8-15 分。这是真实的改进。但——

**发现三：改进不可累加。**

第二轮反馈不会在第一轮基础上继续提升。因为 Agent 执行第二轮修改时，会把第一轮已经改好的内容"回退"掉——最高回退率达 24%。三轮改下来，净效果和只做一轮差不多。

这三个发现合在一起，画出了一幅清晰的图景：**迭代 ≠ 改进。至少在当前模型能力下不是。**

---

## 我们踩完坑之后做了什么

意识到问题后，我们把流水线的"多轮自改"重新设计了。以下三条原则，每条都是血的教训。

### 原则一：砍掉自反思，换成外部评审

自反思为什么无效？因为同一个模型用同一套"审美"既当作者又当评委，天然看不到自己的盲区。

我们现在用的方案：写作 Agent 用一个模型/prompt，评审 Agent 用另一个模型/prompt，且两者的评估标准是一份外部固定的 checklist，不是 Agent 自己生成的。

效果对比：
- **旧方案**（自反思三轮）：平均分 74，方差大，偶尔回退到 65 以下
- **新方案**（外部评审一轮）：平均分 81，方差小，底线稳定在 75+

少做两轮，反而更好。

### 原则二：增量 Patch，不要全文重写

这是最关键的工程决策。

当你让 Agent "根据反馈重写这篇文章"，它会生成一个全新版本——在这个过程中，之前所有的改进都是"可能被保留也可能被丢弃"的薛定谔状态。

换成增量修改就不一样了：明确告诉 Agent "只修改第 3 段和第 5 段，其他段落原封不动返回"。这样已经改好的部分被锁定，不会被二次污染。

实现很简单：把文章拆成段落列表，只把需要修改的段落 ID 和修改意见传给 Agent，拿回修改后的段落再拼装。多一步 diff，少很多退步。

### 原则三：一轮定胜负的评审设计

既然多轮改进不可累加，那就让那唯一的一轮最大化效果。

我们重新设计了评审 prompt，从"笼统指出问题"变成"结构化诊断"：

```
评审输出格式：
1. 段落编号
2. 问题分类（逻辑/数据/表达/结构）
3. 具体问题描述
4. 修改建议（不是"改好一点"，是"把XX替换成YY"）
5. 优先级（P0必改 / P1建议改 / P2可选）
```

Agent 拿到 P0 的明确修改指令，只改这几处，不动其余。一轮搞定，平均耗时减少 60%，质量提升 20%。

## 更深一层的思考

这件事让我重新审视了一个在 AI 开发者圈子里流行的"直觉"——

**"循环 + 反思 = 涌现式改进"**

这个等式在人类身上成立，因为人类有跨会话的记忆、有元认知、有"我知道我不知道什么"的能力。但当前的 LLM 在单次推理中没有这些。它没有"刚才改过什么"的记忆，每次生成都是从零开始的条件概率采样。

所以所谓的"迭代改进"，本质上是在同一个概率分布上重复采样，偶尔采到更好的，偶尔采到更差的——**除非你通过外部机制改变了输入条件（比如提供具体反馈、限定修改范围）。**

理解这个本质之后，设计决策就清晰了：

1. **不要多轮自循环**——一轮就够，省下来的 token 花在更好的 prompt 上
2. **不要让 Agent 自己决定改什么**——外部评审给出明确的改动清单
3. **不要全文重写**——增量 patch，锁定已有成果
4. **不要用同一个 Agent 既写又改**——分离创作和评审的角色

---

## 一句话总结

**AI 迭代的正确姿势不是"多转几圈"，而是"一轮打透"。**

外部评审 > 自反思。增量修改 > 全文重写。一轮精准反馈 > 三轮模糊循环。

如果你的 Agent 流水线也在做"写 → 反思 → 改 → 反思 → 改"的循环，大概率不是在改进——是在原地转圈。把那个循环拆掉，换成一次到位的外部诊断 + 手术式修改。

效果更好，成本更低，且可预测。

这才是工程。
