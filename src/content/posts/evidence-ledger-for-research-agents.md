## 研究 Agent 最容易假装勤奋

很多团队做研究型 Agent，第一版都会让它「多搜一点、多看一点、多总结一点」。看起来很勤奋：几十个链接、几轮搜索、最后一篇结构完整的报告。

但真正拿去做决策时，问题才暴露出来：哪句话来自哪个来源？哪个来源只是背景信息，哪个来源真的支撑结论？有些查询其实没带来增量，甚至把错误方向带进了报告里。

研究 Agent 的核心风险不是搜得不够多，而是没有证据账。

## 一条结论应该能倒着查

我现在更愿意把研究流程设计成「从结论倒查」：每个关键 claim 都必须绑定 citation；每个 citation 都能回到 query；每个 query 都记录为什么发起、有没有命中、是否被最终使用。

这件事听起来像文档洁癖，但它直接决定产品可信度。

如果一个市场判断说「用户正在反感广告和虚拟货币」，它背后至少要能回答三个问题：这是来自用户评论、媒体报道、竞品价格页，还是我们自己的访谈？样本是什么时间的？有没有相反证据？

回答不上来，这句话就不能进入结论区，最多只能放进「待验证假设」。

## 把搜索动作也纳入评价

过去我们常常只评价最终报告：写得是否完整，结论是否清楚，格式是否漂亮。现在我会额外看三类过程指标。

第一是无支撑主张率。报告里有多少判断没有明确来源？这个指标越低，越适合进入产品决策。

第二是冗余检索率。Agent 搜了十次，如果其中六次只是换词重复，说明问题不在模型不努力，而在检索策略没有被训练。

第三是错误引用率。链接存在不等于支持结论。很多 Agent 会把「相关」当成「证明」，这比没有引用更危险，因为它给了读者虚假的安全感。

这些指标不需要一开始就自动化得很复杂。早期可以用表格记录：claim、query、source、evidence、status、reviewer note。先把账记起来，系统才有改进入口。

## 验收器比更长 Prompt 更重要

如果只靠 prompt 说「请确保引用准确」，Agent 迟早会漏。更可靠的做法是把验收器放进工作流：没有 citation 的段落不能发布；引用不可达要回退；同一来源被过度使用要提示；重要结论必须至少有两类证据交叉。

这里的验收器不一定是复杂模型。脚本、规则、人工抽查都可以。关键是不要让 Agent 自己给自己打满分。

我在工程工作流里也见过类似教训：一次页面看起来修好了，但只有拿最新构建跑一遍，才能确认不是旧产物或局部截图骗了我们。研究任务也是一样，漂亮报告不是验收，证据链才是验收。

## 创业团队该怎么落地

如果你在做投研、舆情、竞品、论文日报或企业知识库，我建议先做一个最小证据账本，而不是先追求全自动深研。

第一步，限制 Agent 只能基于入选来源写作，不能在写作阶段临时编新来源。

第二步，把结论分成三档：已证实、合理推断、待验证假设。不同档位用不同语气，避免把猜测包装成事实。

第三步，保留失败样本。搜到但不支持、来源过期、标题相关但正文无关，这些都很值钱。它们是训练检索策略和审核规则的 hard negatives。

第四步，让用户看见一部分证据账。不是把所有中间过程暴露出来，而是在关键结论旁边给出可追溯来源和置信边界。信任不是靠「我很智能」建立的，是靠「你可以检查我」建立的。

未来的研究 Agent，不会因为读得最多就赢，而会因为最可审计、最少幻觉、最能复盘而赢。

对创业者来说，这也是护城河。模型会越来越像，搜索接口也会越来越像；真正难复制的是你积累的行业问题、证据账本、失败样本和验收规则。

别再只问 Agent 能不能写报告。先问一句：这份报告里的每个判断，能不能倒着查回去？

能倒查，才值得进入决策。
