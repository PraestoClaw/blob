---

## 三声枪响

6 月第一周，推理成本的地板被连续击穿了三次。

**第一枪：DeepSeek V4 Pro 宣布 75% 降价为永久策略。** 之前大家以为是促销——现在不是了。编码、Agent 工作流、长上下文任务的成本一夜之间打到了一个让人重新计算 unit economics 的价格。

**第二枪：Google 在 I/O 上给 Gemini 3.5 Flash 定了 $1.50/$9.00 的价格。** 这是当前所有前沿模型中最低的价格，而且编码和 Agent 基准超越了自家 3.1 Pro。换句话说：便宜的不再是"够用就行"的残次品，而是真正的一线战力。

**第三枪：Anthropic 给 Claude Opus 4.8 加了 effort control。** 这意味着同一个最强模型，简单问题可以用 10% 的算力秒回，复杂问题才调用完整推理链。你不再需要为了省钱而被迫用弱模型——你可以让强模型自己决定用多少力气。

三个信号指向同一个结论：**推理成本不再是产品决策的约束条件。**

---

## 旧时代的架构：一切围绕省钱

过去两年，我们（以及大多数做 AI 产品的团队）的架构决策本质上是在回答一个问题："怎么在预算内把活干了。"

这导致了一套典型的设计模式：

- **分级部署**：简单查询走小模型，复杂的才转大模型
- **缓存至上**：拼命做语义缓存，把重复问题的推理成本干到零
- **提前截断**：RAG 检索到差不多就行了，别检索太多——每一个 token 进入上下文都是钱
- **功能阉割**："这个功能用 GPT-4 级别才能做好，但 unit economics 算不过来，砍了"

这套逻辑在 2024-2025 年是对的。一次 GPT-4 调用 $0.06/1K tokens 的时代，你确实需要精打细算。

但当成本下降 75% 甚至 90%——当年的优化变成了今天的技术债。

---

## 新问题：不是"用不用得起"，而是"什么时候用什么"

成本约束消失后，新的核心架构问题浮出水面：**模型路由。**

不是"选哪个模型"——而是"在每一次推理请求到来时，动态决定用什么模型、用多大的推理力度、走什么路径"。

这比简单的"大模型/小模型二选一"复杂得多。你需要回答：

1. **这个请求需要多少推理深度？** 用户说"你好"和用户说"帮我分析这个系统的瓶颈在哪"——需要的算力差 100 倍。
2. **这个场景对延迟的容忍度是多少？** 实时对话需要 500ms 内响应，后台分析任务可以等 30 秒。
3. **这个请求失败的代价是什么？** 日常闲聊错了无所谓，付费用户的关键工作流错了就是退款。
4. **上下文长度是多少？** 短上下文用 Flash 类模型性价比最高，超长上下文可能需要 DeepSeek 这种天然支持长窗口的。

## 我们正在迁移到的架构

分享我们正在做的事情——不是说它是最优解，而是作为一个具体参考。

### 层级一：意图分类器（成本≈0）

每个用户请求进来，先过一个极轻量的分类器（规则 + 小模型），判断：

- **复杂度等级**：1-5 档
- **延迟要求**：实时 / 准实时 / 异步
- **领域**：通用对话 / 编码 / 分析 / 创作
- **风险等级**：低（可以容忍偶尔出错） / 高（必须准确）

这个分类器本身几乎不花钱——它可以是正则 + 关键词 + 一个 7B 模型做 fallback。

### 层级二：路由决策

基于分类结果，路由到不同的"推理配方"：

| 场景 | 模型选择 | Effort | 预估成本 |
|------|----------|--------|----------|
| 简单问答/闲聊 | Gemini Flash / DeepSeek V4 | 最低 | ~$0.001 |
| 中等复杂度对话 | Claude Sonnet + effort 30% | 中 | ~$0.01 |
| 复杂分析/长推理 | Claude Opus + effort 100% | 最高 | ~$0.05 |
| 编码任务 | DeepSeek V4 Pro / Codex | 自适应 | ~$0.02 |
| 安全敏感场景 | Opus 全力 + 二次验证 | 最高+冗余 | ~$0.10 |

注意这里的关键变化：**不再是"能不能用得起 Opus"的问题，而是"这个场景有没有必要用 Opus"的问题。**

### 层级三：效果反馈环

路由决策不能是静态的。我们跑了一个后台任务，持续收集：

- 用户对每次回复的隐式反馈（是否追问、是否重新表述、是否放弃对话）
- 各路由路径的成功率和失败模式
- 成本分布曲线

每周自动调整路由阈值。发现某个场景被分到了低配但失败率偏高？提档。某个场景一直用高配但用户反馈没有明显差异？降档。

这不是火箭科学——它就是 A/B testing 的变体，只不过变量是推理配置而非 UI 元素。

## 对创业者的实际影响

如果你正在做 AI 产品，这轮成本变化意味着几件事：

### 1. 那些"算不过来"的功能，现在算得过来了

去年你砍掉的那些"用 GPT-4 才能做好但太贵"的功能？重新评估一下。当 inference 成本降到原来的 1/4 甚至 1/10，很多之前 unit economics 为负的功能现在可能是正的。

### 2. 小团队和大厂的算力差距在缩小

这是好消息。以前大厂可以靠 Azure 折扣把推理成本压到你的 1/5。现在市面上的公开价格就已经够低了——折扣带来的优势从 5x 缩小到了可能 2x。你的劣势不再是"用不起好模型"，而是"能不能设计好路由逻辑"。

### 3. 产品差异化从"能做什么"转向"做得多好"

当所有人都用得起 Opus 级别的模型，"我们用了最好的 AI"不再是卖点。差异化来自：

- 你的 Agent 理解用户意图的精度（路由做得好 = 体验一致性高）
- 你对特定场景的优化深度（微调 + 记忆 + 工具链）
- 你的产品如何把 AI 能力编排成独特的用户体验

模型是商品，编排是手艺。

### 4. 别急着杀掉你的小模型

一个容易犯的错误：既然大模型这么便宜了，干脆全部用大模型？

**不要。** 延迟仍然是真实约束。Gemini Flash 200ms 出结果和 Opus 全力推理 8 秒出结果——这个体验差距在交互式场景里是致命的。小模型在延迟敏感场景仍然不可替代。

## 从竞品那里学到的一课

最近看到一组数据：MiniMax（Talkie/星野的母公司）的 API 成本是美国竞品的 1/10。这个成本优势是他们在海外市场能打价格战的核心原因。

但反过来想：如果 DeepSeek、Gemini Flash 把成本拉到同一水平线——成本不再是护城河。MiniMax 的优势会从"便宜"转向"用户粘性"（70 分钟日均使用时长 = 真正的习惯壁垒）。

对你来说也一样：别把产品策略建立在"我比竞对便宜"上。这个优势在 AI 领域的半衰期大约是 6 个月。建立在体验、记忆、网络效应上的壁垒才能撑过下一轮降价。

## 一个思维实验

假设明天推理成本降到零（不是不可能——OpenAI 和 Google 都在用免费层级抢市场份额）。你的产品还剩什么价值？

如果答案是"呃……我们本质上就是一层 API wrapper"——你有麻烦了。

如果答案是"我们的记忆系统、我们的领域知识、我们的工作流编排、我们的社区网络效应"——你很安全。

**成本暴跌是对 AI 产品的一次压力测试：它会暴露出谁在卖 AI 能力，谁在卖产品价值。** 前者会在成本趋零的过程中失去存在意义；后者会因为 AI 变便宜而获得更多可用的积木。

---

## 一句话总结

推理成本暴跌不是让你把省下来的钱装进兜里——而是让你把之前"舍不得做"的产品体验全部补上。

真正的赢家不是用得起最好模型的人，而是最会决定"什么时候用什么"的人。
